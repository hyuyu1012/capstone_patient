## 원인: 권한 요청 순서 (닭-달걀 구조)

매니페스트는 정상이다.

```xml
<uses-permission android:name="android.permission.RECORD_AUDIO"/>
<uses-permission android:name="android.permission.FOREGROUND_SERVICE"/>
<uses-permission android:name="android.permission.FOREGROUND_SERVICE_MICROPHONE"/>
...
<service android:foregroundServiceType="microphone" ... />
```

문제는 **런타임 호출 순서**다. `lib/sensing/med_sensing_binder.dart`:

```dart
WidgetsBinding.instance.addPostFrameCallback((_) async {
  await _controller.requestPermissions();  // 알림 + 배터리 예외만 요청
  _controller.init();
  await _controller.start();                // ← 마이크 FGS 시작 → 크래시
});
```

- `requestPermissions()`(`sensing_foreground_controller.dart`)는 **알림 권한과 배터리 최적화 예외만** 요청한다. `RECORD_AUDIO`는 요청하지 않는다.
- 실제 마이크 권한 요청은 서비스 isolate 안의 `med_sensing_service_io.dart._ensureMicPermission()`에 들어있다.
- 그러나 Android 14+(이 기기 targetSDK 36)에서는 **`startForeground(microphone)` 호출 시점에 이미 `RECORD_AUDIO`가 부여돼 있어야** 한다.
- `RECORD_AUDIO`가 부여되기 전에 `start()`가 먼저 호출되어 SecurityException 발생 → 정작 권한을 요청하는 isolate 코드는 영영 도달하지 못한다.

## 수정 방안

메인 isolate에서, 앱이 포그라운드인 상태(즉 `start()` 호출 전)에서 `RECORD_AUDIO`를 먼저 받고, 거부되면 `start()`를 호출하지 않는다. `permission_handler`는 이미 의존성에 포함돼 있다.

`sensing_foreground_controller.requestPermissions()` 내부 또는 `start()` 직전에 추가:

```dart
final mic = await Permission.microphone.request();
if (!mic.isGranted) {
  // start() 호출하지 말고 UI에 "마이크 권한 필요" 안내
  return;
}
```

그리고 binder에서 `start()`를 권한 통과 시에만 호출하도록 가드한다. 이렇게 하면 마이크 FGS가 정상 기동하고 재시작 루프가 사라진다.
